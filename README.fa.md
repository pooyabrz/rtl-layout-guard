# RTL Layout Guard — راهنمای فارسی

نسخهٔ **۰٫۱٫۰** افزونه‌ای قابل نصب برای بررسی متن راست‌به‌چپ، LaTeX و چیدمان رابط کاربری است. کد پروژه با TypeScript نوشته شده و برای توسعهٔ بعدی آماده است.

## نصب سریع

۱. در VS Code بخش Extensions را باز کنید.

۲. از منوی سه‌نقطه، **Install from VSIX…** را بزنید.

۳. فایل `rtl-layout-guard-0.1.0.vsix` را انتخاب کنید. اگر برنامه خواست، پنجره را Reload کنید.

VS Code نسخهٔ ۱٫۹۵ یا جدیدتر لازم است. برای استفاده به حساب کاربری، کلید API یا اجرای سرور نیاز ندارید. این نسخه هنوز در Marketplace منتشر نشده است.

## امتحان‌کردن نسخهٔ اول

فایل‌های پوشهٔ `examples` را باز کنید. پیشنهادها در پنل **Problems** و کنار کد دیده می‌شوند. روی پیشنهاد بروید و `Ctrl+.` بزنید تا اصلاح‌های پیشنهادی ظاهر شوند.

- `layout.css`: پیشنهاد ویژگی‌های منطقی به‌جای سمت فیزیکی چپ و راست.
- `component.tsx`: بررسی کلاس‌های Tailwind و استایل‌های React.
- `persian.tex`: بررسی متن فارسی و انگلیسی در یک سند XePersian.
- `chapter.tex`: نمونهٔ تشخیص تنظیمات از فایل ریشهٔ LaTeX.
- `text.md`: متن فارسی، عربی و عبری برای آزمایش پیش‌نمایش.
- `unicode-controls.txt`: نمونه‌ای شامل کاراکترهای واقعی و نامرئی کنترل جهت.

افزونه به‌صورت خودکار فایل را اصلاح نمی‌کند. فیزیکی‌بودن یک فاصله یا موقعیت الزاماً اشتباه نیست. برای CSS و Tailwind دو تعبیر پیشنهاد می‌شود: معادل سمت موردنظر در طراحی چپ‌به‌راست یا در طراحی راست‌به‌چپ. پیش از اعمال، انتخاب درست را با طراحی تطبیق دهید.

## LaTeX

در سندی که XePersian دارد، برای مثال:

```tex
این مقاله درباره React و TypeScript است.
```

برای کلمه‌های لاتین، اصلاح‌هایی مانند نمونهٔ زیر پیشنهاد می‌شود:

```tex
این مقاله درباره \lr{React} و \lr{TypeScript} است.
```

با انتخاب متن و اجرای دستور **Wrap Selected Text as LTR** یا **RTL**، در XePersian از `\lr{...}` و `\rl{...}` استفاده می‌شود. برای bidi و تنظیمات شناخته‌شدهٔ Polyglossia، دستورهای `\textLR{...}` و `\textRL{...}` به کار می‌روند. بدون تشخیص بستهٔ مناسب، دستور تعریف‌نشده‌ای وارد فایل نمی‌شود.

برای فصل‌های جداگانه، این توضیح را بالای فایل بگذارید:

```tex
% !TeX root = ../main.tex
```

فایل ریشه باید داخل همان پوشهٔ اصلی بازشده در VS Code باشد. اگر تنظیمات از یک پیش‌درآمد سفارشی و غیرمستقیم می‌آید، گزینهٔ `rtlLayoutGuard.latex.directionPackage` را متناسب با پروژه روی `xepersian` یا `bidi` بگذارید.

فرمول‌ها، کامنت‌ها، محیط‌های شناخته‌شدهٔ کد، ارجاع‌ها، آدرس‌ها و متن‌هایی که از قبل داخل دستور جهت‌دهی هستند، در قاعدهٔ متن ترکیبی بررسی نمی‌شوند. این تشخیص بر پایهٔ متن منبع است و همهٔ ماکروها و بسته‌های سفارشی TeX را تفسیر نمی‌کند.

برای تولید PDF باید توزیع TeX، بسته‌های لازم و قلم مناسب را داشته باشید. نمونهٔ فارسی با XeLaTeX و قلم `DejaVu Sans` تنظیم شده؛ قلم را می‌توانید با قلم فارسی نصب‌شدهٔ خودتان جایگزین کنید.

## پیش‌نمایش نوشتار راست‌به‌چپ

در Command Palette، عبارت `RTL Guard` را جست‌وجو و **Open Direction-Aware Text Preview** را اجرا کنید. سه حالت **Auto per line**، **Right to left** و **Left to right** در دسترس است. با تغییر متن، پیش‌نمایش به‌روز می‌شود.

این نما برای خواندن **متن منبع** است؛ فایل LaTeX را به PDF تبدیل نمی‌کند و HTML یا Markdown را هم اجرا یا رندر معنایی نمی‌کند. جهت حرکت مکان‌نما در ادیتور اصلی VS Code را تغییر نمی‌دهد و فایل‌های داخلی برنامه را دست‌کاری نمی‌کند.

## پوشش عمومی متن

در همهٔ فایل‌های متنیِ باز، کاراکترهای واقعی کنترل جهت Unicode بررسی می‌شوند؛ از جمله overrideها و کنترل‌هایی که در همان پاراگراف جفت بسته‌شونده ندارند. نبودن جفت بسته‌شونده همیشه به معنی متن نامعتبر نیست و ممکن است عمدی باشد. نیم‌فاصلهٔ فارسی و ZWJ خطا محسوب نمی‌شوند.

با **Inspect Invisible Direction Controls** می‌توانید نام و محل کنترل‌های نامرئی را ببینید. دستورهای Wrap در فایل‌های غیر LaTeX از جفت‌های ایزولهٔ Unicode استفاده می‌کنند؛ فقط متن یا محتوای رشته را انتخاب کنید، نه نام متغیر یا دستور برنامه. نمایش درست این کنترل‌ها در نرم‌افزار مقصد به پشتیبانی آن نرم‌افزار بستگی دارد.

در نسخهٔ اول، متن عادی و Markdown امکانات عمومی Unicode و پیش‌نمایش را دارند. قواعد تخصصی هر قالب فقط برای قالب‌های پیاده‌سازی‌شده فعال‌اند؛ پشتیبانی از هر نوع فایل به معنای تفسیر همهٔ قواعد آن قالب نیست.

## تنظیمات کاربردی

```json
{
  "rtlLayoutGuard.latex.directionPackage": "auto",
  "rtlLayoutGuard.preview.direction": "auto",
  "rtlLayoutGuard.workspace.maxFiles": 500,
  "rtlLayoutGuard.maxFileSizeKB": 512,
  "rtlLayoutGuard.ignoredRules": []
}
```

از **Scan Workspace** برای بررسی گروهی فایل‌ها استفاده کنید. الگوی فایل‌های بررسی‌شونده، پوشه‌های کنارگذاشته‌شده و سقف تعداد فایل‌ها قابل تنظیم است. برای کم‌کردن پیشنهادهای غیرضروری، شناسهٔ قاعده را در `ignoredRules` بگذارید؛ فهرست کامل قواعد در راهنمای انگلیسی است.

تمام پردازش در دستگاه خودتان انجام می‌شود. افزونه داده‌ای ارسال نمی‌کند و هنگام استفاده، دستور ترمینال یا کامپایلر اجرا نمی‌کند.

## ادامهٔ توسعه

در پوشهٔ پروژه، با Node.js نسخهٔ ۲۰ یا جدیدتر:

```sh
npm ci
npm run check
npm test
npm run build
```

سپس پروژه را در VS Code باز کنید و **F5** بزنید. یک پنجرهٔ آزمایشی با نمونه‌ها باز می‌شود. کد قواعد در `src/core` و اتصال به VS Code در `src/extension.ts` قرار دارد.

برای انتشار در Marketplace، باید شناسهٔ موقت `rtl-layout-guard-dev` را با شناسهٔ ناشر خودتان جایگزین کنید. فایل فعلی برای نصب مستقیم و آزمایش آماده شده است.
